# Choose Your Starting Point

Start with the next thing you want to understand or do. Your job title does not need to match the collection you open.

| Your starting point | Try this route |
| --- | --- |
| You are new to command-line work | [Learning libraries](../08-learning-libraries/) → The Missing Semester; use [systems tools](../04-tools-and-technologies/README.md#systems-and-scripting) when a tool becomes relevant |
| You write applications and want to deliver them | [Delivery tools](../04-tools-and-technologies/README.md#source-and-delivery) and [containers](../04-tools-and-technologies/README.md#containers) |
| You administer hosts or repeat manual tasks | [Systems and scripting](../04-tools-and-technologies/README.md#systems-and-scripting), then [configuration tools](../04-tools-and-technologies/README.md#infrastructure-and-configuration) |
| You want to understand network traffic | [Wireshark discoveries](../04-tools-and-technologies/wireshark.md); start with a saved capture before capturing live traffic |
| You operate a service and want better evidence | [Metrics and monitoring](../04-tools-and-technologies/README.md#metrics-and-monitoring) and [logs and tracing](../04-tools-and-technologies/README.md#logs-and-tracing) |
| You want to explore a different responsibility | [Compare career directions](../02-career-paths/) |
| You learn best by doing | [Practice websites and challenges](../06-hands-on-practice/) |

## Choose the format that suits the question

Watch a demonstration when you need to see a workflow. Read a reference when exact behavior matters. Try an exercise when you want to check your understanding. Use a case study when you want to examine another engineer’s reasoning.

Keep one small result from your visit: a useful explanation, an annotated capture, a working example, or a better question. Return to the directory when the next gap appears.
