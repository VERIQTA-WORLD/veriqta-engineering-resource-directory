# Choose Your Starting Point

Start with the question you need answered today. You can explore a new career, fill a knowledge gap, or investigate a failure without following the same path as everyone else.

| Where you are now | A useful first move |
| --- | --- |
| New to command-line and infrastructure work | Explore [Linux](../03-topics/linux.md), [networking](../03-topics/networking.md), and [Git](../04-tools/git.md) |
| Writing applications and learning how to run them | Start with [containers](../03-topics/containers.md), [Docker](../04-tools/docker.md), and [CI/CD](../03-topics/cicd.md) |
| Administering systems and repeating manual tasks | Explore [scripting](../03-topics/scripting.md), [Ansible](../04-tools/ansible.md), and [Infrastructure as Code](../03-topics/infrastructure-as-code.md) |
| Preparing for a different engineering responsibility | Choose a [career path](../02-career-paths/) |
| Already working with a specific technology | Open its [tool collection](../04-tools/) |
| Trying to diagnose a failure | Start with [troubleshooting](../07-troubleshooting/) |

## New to infrastructure? Build a small foundation

Learn enough to navigate files, understand a running process, explain a network connection, and track a change. Practise those ideas together rather than collecting separate tool introductions.

**[The Missing Semester →](https://missing.csail.mit.edu/)**  
Use its command-line and workflow material to become more comfortable working in a terminal. Follow the exercises with the prerequisites given for each lesson.  
**Free online · Course material · Basic programming familiarity helpful**

**[Pro Git →](https://git-scm.com/book/en/v2)**  
Start with Getting Started and Git Basics. Use a small local repository to inspect changes and explain what a commit records.  
**Free online · Book · Beginner onward**

## Ready to move from code to a running service?

Follow one application through packaging, configuration, startup, and a useful request. Start with Docker if containers are new; choose Kubernetes when you need to understand orchestration.

## Already operating services?

Choose the responsibility you want to strengthen: [SRE](../02-career-paths/sre.md), [platform engineering](../02-career-paths/platform-engineering.md), [observability](../02-career-paths/observability.md), or [cloud security](../02-career-paths/cloud-security.md).

**[The Site Reliability Workbook →](https://sre.google/workbook/table-of-contents/)**  
Read the chapter matching your current concern, such as service objectives, alerting, releases, or incident response.  
**Free online · Book · Service-operation experience helpful**

If you are handling an active failure, go directly to [troubleshooting](../07-troubleshooting/) and follow your service’s response process.
