## Resource organisation

The intended design keeps each tool in one canonical record, then cross-references it from careers, domains, ecosystems, and production problems. The blueprint's Wireshark example is [networking/packet-analysis/wireshark.md](02-tools/networking/packet-analysis/wireshark.md), with intended ID `TOOL-NET-001`. Its file and the permanent [ID registry](12-indexes/id-registry.csv) are empty in this scaffold.

Never recycle an assigned resource ID. Smaller cloud providers should mark unsupported categories as N/A when their pages are written.

## Build the content in batches

1. Fill the root policies and [start-here guides](00-start-here/).
2. Write the [templates](14-templates/), [catalog schema](13-resource-catalog/), and [ID and browsing indexes](12-indexes/).
3. Complete one career, tool category, domain, or production problem at a time.
4. Verify each resource's source, metadata, relationships, and links before marking it reviewed.
5. Implement [automation](17-automation-scripts/) and [site search](18-site-and-search/) after their requirements are defined.

The file sets for careers, domains, cloud providers, ecosystems, and production problems have already been expanded throughout the repository.
