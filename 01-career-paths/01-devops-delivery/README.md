# DevOps delivery career resources

Delivery workflows, automation, infrastructure, shared platforms, architecture, and technical improvement.

[All career categories](../README.md) · [Repository home](../../README.md)

The six collections below contain substantial resource drafts. Source and integration review is still in progress; practical links have not been runtime-tested as deployments. Choose a scope that matches your task.

| Career | Collection focus |
| --- | --- |
| [DevOps architect](devops-architect/README.md) | Design decisions across delivery, infrastructure, identity, platform services, reliability, cost, and operational responsibility. |
| [DevOps automation engineer](devops-automation-engineer/README.md) | This collection focuses on the code and workflows that automate delivery and operations: scripts, infrastructure changes, configuration, API integrations, tests, and recovery paths. The central question is whether an operation is repeatable, observable, appropriately authorized, and recoverable when only part of it succeeds. |
| [DevOps consultant](devops-consultant/README.md) | This collection supports technical assessment and improvement work across software delivery and operations. It emphasizes evidence gathering, architecture review, delivery flow, operating ownership, security, reliability, cost, and practical implementation options. The resources help evaluate a client environment and justify a recommendation with testable assumptions. |
| [DevOps engineer](devops-engineer/README.md) | This collection covers implementing and operating software delivery workflows: source control, builds, infrastructure and configuration, deployment, observability, security, and recovery. It gives readers practical references for connecting those systems and investigating the failures that occur between them. |
| [DevOps infrastructure engineer](devops-infrastructure-engineer/README.md) | This collection focuses on the infrastructure that supports software delivery and production workloads: cloud foundations, machine images, host configuration, provisioning state, networking, identity, compute, storage, observability, and recovery. It connects infrastructure changes to the delivery workflows and operating evidence needed to manage them. |
| [DevOps platform engineer](devops-platform-engineer/README.md) | This collection focuses on shared capabilities that help teams build, deliver, and operate software: pipeline services, developer interfaces, reusable infrastructure, deployment controls, identity, artifact services, telemetry, and platform recovery. It emphasizes the platform as an operated service with defined users, interfaces, ownership, and limits. |

Browse by engineering task; the directory does not impose a curriculum.
