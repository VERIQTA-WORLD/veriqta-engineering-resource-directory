# DevOps consultant

This collection supports technical assessment and improvement work across software delivery and operations. It emphasizes evidence gathering, architecture review, delivery flow, operating ownership, security, reliability, cost, and practical implementation options. The resources help evaluate a client environment and justify a recommendation with testable assumptions.

Consulting engagements differ in authority and scope. Agree access, data handling, decision ownership, and implementation responsibility before conducting an assessment or experiment. Recommendations should reflect the client workload and constraints, not a preferred stack.

## Useful entry points

Choose the reference that matches your immediate task. These links are starting points into the wider collections, not a required sequence.

| Resource | When to open it | Level and access |
| --- | --- | --- |
| [DORA Guides](https://dora.dev/guides/) | Explore delivery measurement, value-stream analysis, and improvement guidance. | Intermediate; use measures to investigate system behavior rather than rank individuals. |
| [DORA software delivery metrics guide](https://dora.dev/guides/dora-metrics/) | Select delivery measurements and interpret them as improvement signals. | Foundation onward; public research-program guidance. Define measurement context; avoid using aggregate metrics to rank individual engineers. |

## Coverage and practical use

delivery assessment and measurement; value stream and organizational boundaries; tool and operating-model comparison; cloud and platform architecture review; security and software supply chain; reliability and recovery evidence; migration, implementation, cost and handover.

Continuous integration and continuous delivery (CI/CD) describe connected delivery practices. Infrastructure as code (IaC) describes infrastructure managed through versioned configuration or code. GitOps resources address desired-state delivery and reconciliation. Use each approach only where its responsibilities and failure behavior are understood.

Official external destinations are used while the repository catalog is being established. Software, hosted-service, and cloud charges must be assessed separately from public access to a reference. Source review does not certify a deployment, a full course, or an entire book.
