# DevOps Consultant: Labs and Portfolio Projects

## Assess a synthetic delivery stream

Create fictional change records containing active work, waiting, rework, and release verification.

Produce an evidence register, a change-path map, two competing hypotheses, and a prioritized pilot recommendation.

### Environment and access

A spreadsheet or document editor is enough. Use fictional organizations and label all records synthetic.

### Challenge the result

Remove one important data field and explain how it limits your conclusion. Change the release mix and revisit the comparison.

A synthetic assessment demonstrates method, not a real client improvement or business result.

### Cleanup

Delete any temporary datasets containing private material if you adapted the exercise. Synthetic portfolio records can remain with clear labeling.

## Compare a platform request with a smaller intervention

A fictional sponsor wants a portal while developers report slow access and repeated environment repairs.

Produce a discovery brief, alternatives, total ownership considerations, a pilot, and a stop-or-expand decision.

### Environment and access

Design-only work needs no accounts. If you prototype, use synthetic repositories and integrations.

### Challenge the result

Assume the available operating capacity is halved. Explain which option remains feasible and what scope you would reduce.

Do not label stakeholder assumptions as research findings or present the hypothetical benefit as measured.

### Cleanup

Remove optional prototype resources and credentials. Retain assumptions, source attribution, and the decision history.

## Demonstrate an accepted handover

Use a small disposable workflow as the subject of a consulting-style handover.

Write installation and support notes, access requirements, a failure exercise, acceptance checks, and an outstanding-risk record.

### Environment and access

You need an owned test repository, appropriate runner access, and a second reviewer if available. A solo self-review must be labeled as such.

### Challenge the result

Have the reviewer diagnose a deliberately invalid configuration using only the handover material. Record where assistance was still needed.

A successful handover exercise covers this workflow and reviewer; it does not prove organization-wide adoption.

### Cleanup

Remove temporary access and scheduled execution. Confirm who owns any retained repository and integration.
