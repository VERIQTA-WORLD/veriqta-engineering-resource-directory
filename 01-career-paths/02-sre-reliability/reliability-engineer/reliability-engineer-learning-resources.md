# Reliability Engineer: Learning Resources

Begin with the user outcome, then examine propagation and alternatives. Use incident learning to challenge whether the proposed control would have changed the observed result.

## Define the outcome

Read [Implementing SLOs](https://sre.google/workbook/implementing-slos/), beginning with selecting indicators, targets, and the improvement process.

Write the user behavior, eligible population, objective window, and data-quality assumptions.

## Explore failure propagation

Read [Google SRE: Addressing Cascading Failures](https://sre.google/sre-book/addressing-cascading-failures/), beginning with overload, feedback loops, and recovery discussion.

Identify a trigger, amplification path, shared resource, and potential containment boundary.

## Compare interventions

Read [Architecture Decision Records](https://adr.github.io/), beginning with the introductory explanation and a suitable template.

Write two feasible options and the observation that would change the preferred decision.

## Learn from an incident

Read [Google SRE Workbook: Postmortem Culture](https://sre.google/workbook/postmortem-culture/), beginning with incident analysis, action items, and organizational learning.

Separate the timeline, supported explanations, unresolved questions, and owned improvement actions.

Choose a [project](reliability-engineer-labs-and-portfolio-projects.md) when you need execution evidence, or work through the [assessment scenarios](reliability-engineer-interview-and-assessment-resources.md) to apply the idea under changed conditions.
