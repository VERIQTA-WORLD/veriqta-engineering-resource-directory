# Reliability Engineer: Labs and Portfolio Projects

## Build a service reliability model

Choose a fictional user journey and connect its objective to dependencies and failure scenarios.

### Set up the exercise

A document or spreadsheet is sufficient. Use synthetic events and explicitly stated requirements.

### Investigate the behavior

Assume all component dashboards are healthy while one user journey fails. Redefine evidence to capture the actual outcome.

Produce indicator definitions, eligible events, important populations, dependency risks, and a prioritized validation plan.

### Finish and clean up

Remove optional prototype resources. Keep assumptions and synthetic observations clearly distinguishable in the retained material.

## Prioritize an improvement with evidence

Compare three reliability actions against a synthetic incident and operating record.

### Set up the exercise

Use fictional incidents, costs, effort, and ownership. No production access is needed.

### Investigate the behavior

Change one constraint, such as recovery time or staffing, and revisit the decision. Identify where evidence is insufficient.

Write alternatives, expected mechanisms, owner, acceptance condition, and the result that would reverse the recommendation.

### Finish and clean up

Delete any private source records used to inspire the exercise. Retain only sanitized or synthetic portfolio material.
