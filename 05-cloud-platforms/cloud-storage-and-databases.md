# Cloud Storage and Databases

Choose resources from the data access, persistence, and recovery needs of your application.

## Start with the data lifecycle

| Open | What you can find | Access |
| --- | --- | --- |
| [Amazon S3 user guide](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html) | Read object, bucket, and access guidance before experimenting with data. | Free reference; storage and requests can cost money |
| [Azure Storage](https://learn.microsoft.com/en-us/azure/storage/) | Choose object, file, or other storage material for your data-access need. | Free reference; service charges may apply |
| [Google Cloud Storage](https://cloud.google.com/storage/docs/introduction) | Study object storage and its access model. | Free reference; storage and requests can cost money |
| [The Art of PostgreSQL](https://theartofpostgresql.com/) | Dimitri Fontaine; deepen SQL reasoning with a PostgreSQL-focused book. | Paid book; author samples |
| [Designing Data-Intensive Applications](https://dataintensive.net/) | Martin Kleppmann’s author site; compare editions and select the data-system question you need to study. | Paid book; author resources |

## Choose a bounded exercise

Use synthetic data to demonstrate write, read, permitted access, and recovery or retention behavior in a dedicated learning scope. Check the selected guide’s permissions, region, account, and resource requirements before starting. Follow its teardown, revoke temporary access, and inspect retained disks, snapshots, addresses, logs, or other billable resources afterward.
